# P1.3 — REGISTRO DE DECISIONES

> Cada decisión arquitectónica registra: problema, opciones, evidencia,
> decisión, consecuencias y qué podría revocarla.
>
> En esta misión **no se ha tomado ninguna decisión de producción**. Todas las
> decisiones son de *investigación*: qué mirar, qué no tocar, qué etiqueta usar.

---

## D-001 — No tocar `servicio_consulta.py`

```
Problema: P1.3 Podría "arreglar" la semántica de state_version aquí.
Opciones:
  (a) Redefinir state_version como identidad de estado
  (b) Dejarlo intacto y solo documentar
Evidencia: Ninguna — no hay mecanismo de estado demostrado (P1.3_CANDIDATOS).
DECISIÓN: (b). Fichero intacto.
Consecuencias: La limitación persiste y queda documentada. Es preferible a
  publicar un `state_version` que miente.
QUÉ PODRÍA CAMBIARLA: que un experimento con DF demuestre X1+X2 (persistencia
  y comportamiento ante duplicado) Y exista un mecanismo de congelación (X3).
```

## D-002 — Herramientas de investigación en `dfchron/pruebas/p1_3/`

```
Problema: ¿Dónde vive el código auxiliar de la investigación?
Opciones:
  (a) `dfchron/` (paquete productivo) — mezclado con el producto
  (b) `00_SOURCE/tools/` — junto al extractor ya existente
  (c) `dfchron/pruebas/p1_3/` — separado, bajo pruebas
DECISIÓN: (c).
Consecuencias: Nada del producto importa estas herramientas. Queda trazado
  inequívocamente como investigación (§22.4).
RIESGO RESIDUAL: `dfchron/pruebas/` contiene ya tests del producto; conviven,
  pero el subdirectorio `p1_3/` los separa.
```

## D-003 — Analizadores de save de SOLO LECTURA

```
Problema: Investigar la estructura del save sin destruir evidencia.
Opciones:
  (a) Parser que escribe sobre los saves — inaceptable
  (b) Parser que reescribe el payload a disco (como el extractor previo)
  (c) Lectura en memoria, sin escribir nada derivado
DECISIÓN: (c). `forense_save.py` abre con 'rb', descomprime en memoria y no
  escribe ningún `.bin`.
Consecuencias: No se genera `world_decompressed.bin` (208 MB que el extractor
  previo sí dejó). Reutiliza el conocimiento del formato ya documentado en
  `00_SOURCE/extraction/tools/decode_container.py`, sin duplicar sus salidas.
NOTA: el `.bin` de 208 MB ya existente se deja intacto (no se borra, §36).
```

## D-004 — Mtime registrado pero marcado como NO identidad

```
Problema: `world.json` y el informe previo usan `source_mtime` como si fuera un
  dato de identidad.
Evidencia: E007 — dos ficheros byte a byte idénticos con mtimes distintos.
DECISIÓN: registrar `mtime_observado` pero con el campo EXPLÍCITO
  `mtime_es_identidad: false` al lado, para que ningún consumidor futuro lo lea
  como identidad por descuido.
Consecuencias: Autodocumentante. El dato no se pierde (no se borra información),
  pero queda marcado.
```

## D-005 — Sin prototipo `P1.3_PROTOTIPO_ESTADO`

```
Problema: §24 permite crear un prototipo si la evidencia lo justifica.
Evidencia: El único candidato (dfhack.persistent) está `NO DEMOSTRADA`, y no
  se ha podido ejecutar DF para intentarlo siquiera.
DECISIÓN: **NO crear el prototipo.**
Consecuencias: Se respeta el espíritu de §24 ("si la evidencia lo justifica").
  Aquí no lo justifica: sin X1/X2 resueltos, un contador persistente sería un
  campo más que parece una garantía y no lo es.
QUÉ PODRÍA CAMBIARLA: ejecutar E6 y E7 con DF disponible.
```

## D-006 — Resultados negativos se escriben como `NO DEMOSTRADO`, nunca como `NO`

```
Problema: Distinguir "no existe" de "no lo he comprobado".
DECISIÓN: vocabulario estricto en todos los informes:
  - `REFUTADO`      = hay evidencia en contra (ej.: H-004, E007)
  - `NO DEMOSTRADO` = no hay evidencia suficiente, ni a favor ni en contra
  - `NO DISPONIBLE` = el mecanismo no existe en la superficie documentada
Consecuencias: Ninguna conclusión de esta misión es más fuerte que su evidencia.
```

## D-007 — No borrar el `.bin` de 208 MB ya existente

```
Problema: `00_SOURCE/extraction/tools/raw/world_decompressed.bin` (208 MB) es un
  temporal grande que §33 mencionaría como "cero temporales".
Evidencia: No es un temporal de P1.3: es un artefacto de extracción previa,
  documentado y con `_decode_meta.json` que lo referencia.
DECISIÓN: No tocarlo. No es de esta misión y borrarlo destruiría evidencia
  previa (§36).
Consecuencias: Se reporta en §33 como NO TOCADO, con su motivo.
```
