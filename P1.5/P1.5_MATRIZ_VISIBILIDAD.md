# P1.5 — MATRIZ DE VISIBILIDAD

> Principio rector de la misión:
>
> ```
> DFHack KNOWLEDGE  ≠  PLAYER KNOWLEDGE
> PLAYER KNOWLEDGE  ⊂  DF INTERNAL KNOWLEDGE
> ```
>
> El objetivo es **descubrir y formalizar esa frontera**, no suponerla.

## El caso que define la frontera

```
game_tick
   ¿existe internamente?  SÍ
   ¿DFHack lo obtiene?    SÍ
   ¿la interfaz lo muestra? NO
   ¿el jugador puede?    NO
   ↓
   NOT_VISIBLE  ->  BLOQUEADO
```

```
nombre del enano
   ¿existe internamente?  SÍ
   ¿DFHack lo obtiene?    SÍ
   ¿la interfaz lo muestra? SÍ
   ¿el jugador puede?    SÍ
   ↓
   VISIBLE  ->  PERMITIDO
```

**El tick es el ejemplo canónico de la regla de oro**: DFHack lo sabe, el
jugador no. P1.4 ya lo marcó `NO_VISIBLE` y el validador lo comprobaba solo;
P1.5 lo confirma.

## Un hallazgo de método: `isVisible` como filtro

`dfhack.units.isVisible(u)` devuelve si la unidad es **visible para el jugador**.

Eso ofrece una tercera vía, más rigurosa que clasificar dato a dato:

```
Extraer la unidad  ⟶  isVisible(u) == false  ⟶  NO se emite
```

El perímetro deja de ser una convención documental y pasa a ser **una
pregunta que el propio juego responde**. No se ha implementado, pero existe y
es medible.

## Datos que NO se clasifican (y por qué)

| Dato | Por qué `UNKNOWN` |
|---|---|
| Salud detallada, heridas, enfermedades | API noLocalized; sin API probada |
| Pensamientos, emociones, relaciones | Ídem |
| Inventario y equipo | `dfhack.items` existe pero **no se ha ejercido** |
| Edificios, talleres, granjas, stockpiles | `dfhack.buildings` existe pero las funciones que probé **no existen** |
| Militar (escuadras, soldados) | `dfhack.military` tiene **solo 5 miembros**, 2 de escritura |
| Animales, visitantes, migrantes | `isPet()`, `isVisitor()` existen; no ejercitados |
| Historia, eventos, figuras | No investigado |

> **`UNKNOWN` no significa «invisible».** Significa que **no se ha demostrado
> que el jugador pueda verlo**. No autoriza a emitirlo, y tampoco lo descarta.

## Bloqueos explícitos (§26-I)

Estos datos **no deben entrar** aunque DFHack los dé:

| Bloqueado | Motivo |
|---|---|
| `game_tick` como fecha | NOT_VISIBLE |
| `internal.memscan` y compañía | Ingeniería de memoria, prohibida por §9 |
| `dfhack.internal.patchMemory` / `setAddress` | Escritura en memoria del juego |
| Cualquier dato de `df.global` sin equivalente en UI | No hay evidencia de que el jugador lo vea |
