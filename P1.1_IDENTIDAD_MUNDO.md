# DF-Chronicles :: P1.1 — Identidad del mundo en la extracción

> **P1.1 CERRADA — identidad del mundo capturada.
> Identidad del estado vivo todavía abierta.**

**Misión:** capturar y propagar la identidad del mundo que `exportlegends.lua`
ya proporciona, **sin** intentar resolver la identidad del estado.

> Esta misión mejora la identidad del mundo disponible durante la extracción.
> **No proporciona todavía una identidad fiable del estado vivo del mundo.**

Fecha: 2026-10-04 · P1 relacionada: `P1_VERSIONADO_MUNDO_VIVO.md`

---

## 1. Problema

P1 demostró con datos reales que:

| Hecho demostrado | Consecuencia |
| --- | --- |
| `dataset_id` = SHA-256 del contenido de 15 secciones | Identifica **contenido**, no mundo |
| `state_version` **es** `dataset_id` | No hay dos ejes, hay uno con dos nombres |
| Dos extracciones separadas 82 s → mismo `dataset_id` | El reloj no participa |
| Dos mundos con contenido igual → mismo `dataset_id` | **No distingue mundos** |
| `legends.xml` no tiene nombre de mundo, `world_id`, `tick` ni seed | El dato no estaba en el dataset |

Y encontró una pérdida evitable: **`exportlegends.lua` ya escribe la identidad
del mundo en cada ejecución, y el pipeline la descartaba.**

P1.1 recupera ese dato. Nada más.

---

## 2. Evidencia de P1 que sostiene esta misión

De `P1_VERSIONADO_MUNDO_VIVO.md` §20.1, verificado con backups reales:

1. **Experimento A** — dos ejecuciones del pipeline sobre el mismo contenido
   produjeron `v1-04170363943d4ba1` ambas veces.
2. **Experimento C** — el inventario de los 344 tags de `legends.xml` **no**
   contiene `world_name`, `world_id`, `tick` ni `seed`.
3. **`exportlegends.lua:130,139`** escribe `save_dir` y `world_data.name` en
   cada exportación.

**Conclusión:** la identidad del mundo estaba disponible y se perdía. Eso es un
defecto de extracción, no un problema de modelado.

---

## 3. Origen de `world_name`

`exportlegends.lua:139`:

```lua
file:write("<name>"..escape_xml(dfhack.df2utf(
    dfhack.translation.translateName(world.world_data.name))).."</name>\n")
```

Se escribe en la **línea 139**, justo después de `<df_world>` en la línea 138, y
**antes que cualquier otra sección**. Por eso está siempre al principio del
fichero y basta leer la cabecera.

**Comprobado contra el export real del proyecto:**

```
00_SOURCE/original_data/legends_plus.xml  ->  <df_world><name>Orid En</name>
```

Es el único mundo real del que hay evidencia en este repositorio.

---

## 4. Origen de `world_folder`

`exportlegends.lua:130`:

```lua
local filename = world.cur_savegame.save_dir
                   .. "-"..get_world_date_str()
                   .."-legends_plus.xml"
```

`save_dir` **no se escribe en el cuerpo del XML**: solo aparece como prefijo
del **nombre del fichero**. Ejemplo real de DFHack: `region1-00042-03-15-legends_plus.xml`.

### 4.1 Limitación real y ya ocurrida

**Este proyecto copió el fichero y lo renombró a `legends_plus.xml`.** Ese
prefijo se perdió, y no hay forma de recuperarlo del contenido del XML.

Por tanto, **para el dataset actual `world_folder` es irrecuperable**. Se
declara `UNKNOWN` con su motivo. No se inventa, y no se rellena con
`region1` ni con la ruta del save, aunque `00_SOURCE/extraction/*.json` mencione
`...\save\region1\world.sav`: eso es de otro fichero, de otra extracción, y
unirlo sería inventar la relación.

**A partir de la próxima exportación** que conserve el nombre, `world_folder`
se captura sin tocar nada más.

### 4.2 Lo que se descarta deliberadamente

El nombre completo incluye `get_world_date_str()` → `%05d-%02d-%02d`
(`cur_year`-`mes`-`día`). **Esa parte se descarta a propósito.**

P1 demostró que el estado del mundo **no es función del tiempo**
(`timestream` comprime 9 ticks en un frame y el mundo avanza igual). Guardar
esa fecha aquí sería crear una identidad de estado sin haberla demostrado, que
es exactamente lo que la misión prohíbe (reglas 8 y 9).

---
## 5. Cómo se capturan

Módulo nuevo: **`00_SOURCE/tools/identidad_mundo.py`**. Solo biblioteca estándar.

```
identidad_mundo.py
   mundo_nombre(ruta)     -> lee <df_world><name> de la cabecera
   mundo_carpeta(ruta)    -> extrae save_dir del NOMBRE del fichero
   desde_export(ruta)     -> {world_name, world_folder, ...ausencias}
   anadir_a_registro(...) -> inyecta en dataset_version.json
```

Se invoca desde `actualizar_datos.py`, **etapa 8 (Registro)**, justo antes de
`escribir_version()`:

```python
identidad_mundo.anadir_a_registro(
    registro,
    identidad_mundo.desde_export(
        (entradas.get("legends_plus.xml") or {}).get("ruta")))
```

**Reutiliza el mecanismo de metadata existente** (`dataset_version.json`), sin
crear una segunda infraestructura. No hay un fichero nuevo de identidad.

Además, `cmd_estado` muestra el bloque, **incluido cuando falta**:

```
  Identidad del mundo (NO es identidad del estado)
    world_name   : Orid En
    world_folder : UNKNOWN
      world_folder ausente: el nombre del fichero exportado no conserva el
      prefijo save_dir que escribe exportlegends.lua
```

Y el módulo es ejecutable como herramienta manual:

```
python 00_SOURCE/tools/identidad_mundo.py <ruta_export>
```

## 6. Dónde se almacenan

En `00_SOURCE/dataset_version.json`, clave **`mundo`**:

```json
"mundo": {
  "world_name": "Orid En",
  "world_folder": "UNKNOWN",
  "world_name_ausente_porque": null,
  "world_folder_ausente_porque": "el nombre del fichero exportado no conserva
                                  el prefijo save_dir que escribe exportlegends.lua",
  "origen": "exportlegends.lua",
  "campos": "<df_world><name> y prefijo save_dir del nombre del export"
}
```

### 6.1 Aislamiento — por qué esto no rompe nada

`dataset_id` se calcula **antes**, en la misma etapa, y **solo** a partir de
`manifiesto["secciones"]`:

```python
"dataset_id": calcular_dataset_id(manifiesto["secciones"]),   # ← arriba
...
identidad_mundo.anadir_a_registro(registro, ...)               # ← abajo
```

La clave `mundo` **no participa** en la fórmula. Consecuencias:

- El `dataset_id` no cambia. `v1-04170363943d4ba1` sigue siendo `v1-04170363943d4ba1`.
- `es_actual()` y toda la invalidación por dataset siguen igual.
- `servicio_consulta.py`, `api.py` y `web/app.js` **no se han tocado** y no
  necesitan tocarse: leen lo que ya leían.
- Un `dataset_version.json` anterior a P1.1 (sin `mundo`) se tolera: la clave
  falta y el que lee usa `.get("mundo") or {}`.

## 7. Semántica de cada campo

| Campo | Qué es | Qué **NO** es | Origen |
| --- | --- | --- | --- |
| `world_name` | Nombre que DF/DFHack da al mundo durante la exportación | **No** es identificador global único: dos mundos pueden llamarse igual, y uno puede renombrarse | `<df_world><name>` |
| `world_folder` | Carpeta del save, según `save_dir` | **No** es único global: vale dentro del entorno donde se exportó | Prefijo del nombre del export |
| `dataset_id` | Hash del contenido extraído | **No** es identidad del mundo; puede ser idéntico en dos mundos | SHA-256 de `salidas` |
| `state_version` | **Idénticamente** `dataset_id` | **No** es identidad del estado vivo; no es un tick; no es una serie temporal | `dataset_id` |

### 7.1 Las tres afirmaciones que este sistema NO hace

1. ❌ «Este dataset viene del mundo X» → sí puede decirse, con `world_name`.
2. ❌ «Este estado es el del mundo en el momento T» → **no puede decirse**.
3. ❌ «Dos evidencias con el mismo `state_version` son del mismo instante» →
   **falso**, y P1 lo demostró.

---

## 8. Mundo ≠ dataset

```
dataset_id   = f(contenido extraído)   → "¿qué bytes tengo?"
world_name   = "Orid En"               → "¿de qué mundo salieron?"
world_folder = "region1"               → "¿de qué save salieron?"
```

Son **ejes ortogonales**. La prueba `test_el_dataset_id_no_ve_el_mundo`
documenta explícitamente la limitación de P1: dos mundos distintos producen el
**mismo** `dataset_id`. Por eso la identidad de mundo no *mejora* el
`dataset_id`: lo **complementa**.

## 9. Mundo ≠ estado

Esto es lo que P1.1 **no** toca.

| | Identifica | Lo demuestra |
| --- | --- | --- |
| `world_name` | **Qué mundo** | El `<df_world><name>` del propio export |
| `dataset_id` | **Qué contenido** | SHA-256 sobre las 15 secciones |
| Estado vivo | *(nada)* | **Nada. Sigue abierto.** |

`world_folder` y `world_name` **no** se convierten en `state_version`, ni se
combinan, ni se hashean para producirlo. Una prueba lo vigila:
`test_mundo_no_contamina_state_version` comprueba que `DATASET_ID` es distinto
de `world_name` y de `world_folder`.

Y `world_name` **no** es un reloj: un mundo puede llamarse «Orid En» en el año 1
y en el año 200, y seguir siendo el mismo nombre.

## 10. La falsa garantía (PARTE 4)

`contrato_ia.py:105-113` decía:

> *«cambia **exactamente** cuando cambia el mundo, que es lo que hacía falta
> para poder invalidar una evidencia vieja»*

**Es falso**, y P1 lo demostró con datos reales. Corregido **solo en la
docstring**, sin tocar comportamiento:

- Se sustituyó por «cambia cuando cambia el **contenido extraído**».
- Se añadió una sección que dice lo que el campo **NO** es, y por qué.
- La frase «cambia exactamente cuando cambia el mundo» **ya no aparece**, y una
  prueba lo verifica: `test_el_contrato_no_promete_estado_exacto`.

También se corrigió la docstring de `ia_conocimiento.evidencia_de()`, que decía
«anclada al estado del mundo que la produjo».

## 12. Limitaciones

1. **`world_folder` no está disponible hoy** para el dataset activo. Se capturará
   en la próxima exportación que conserve el nombre.
2. **`world_name` no es único.** Dos mundos pueden coincidir. Ninguna prueba de
   este repositorio demuestra lo contrario.
3. **`dfhack.world.ReadWorldFolder()` no se usa.** Existe (documentada en
   `Lua API.txt:2191-2211`) pero requiere DF en ejecución, que no hay. Se usa el
   dato que el propio export ya trae, sin suponer nada de DF.
4. **Discrepancia anotada:** `save_metadata.json` registra
   `candidate_world_name = "A Record of the Forest"` y el export dice
   `«Orid En»`. Son de extracciones distintas y **no se han mezclado**. Queda
   como dato abierto.
5. **El registro activo no se ha reescrito.** `dataset_version.json` conserva su
   contenido; el bloque `mundo` aparecerá en la próxima actualización. Es
   deliberado: esta misión no regenera el dataset.

## 15. Relación con el futuro modelo de estado

`mundo` es **una pieza de entrada**, no el modelo. Cuando P1 se desbloquee:

```text
WorldIdentity    = save_dir + world_data.name          [CAPTURADO en P1.1]
StateIdentity    = ???                                   [ABIERTO]
Lineage          = contador persistente en el save      [NO DEMOSTRADO]
ObservationMeta  = observed_at + suspended             [NO DEMOSTRADO]
```

Lo que P1.1 hace es **quitar el primer bloqueo**: sin `WorldIdentity` no hay base
sobre la que construir nada más. Lo que P1.1 **no** hace es decidir cómo será
`StateIdentity`.

Y una advertencia que P1 dejó escrita y que sigue vigente: la fecha del nombre
del export (`00042-03-15`) **parece** una solución y no lo es. Se descartó a
propósito, y `test_no_se_rellena_con_timestamp` lo vigila.

## 16. Cierre

> **P1.1 CERRADA — identidad del mundo capturada.
> Identidad del estado vivo todavía abierta.**

Lo que esta misión demuestra con datos, no con suposiciones:

- `world_name = "Orid En"` se conserva del export real. ✅
- `world_folder` se conserva cuando el export conserva su nombre. ✅
- Cuando no está, se declara `UNKNOWN` **con motivo**, y nunca se rellena. ✅
- El `dataset_id` sigue siendo `v1-04170363943d4ba1`. ✅
- Ningún campo de estado ha sido creado. ✅
- La falsa garantía del contrato ha sido retirada. ✅
- `servicio_consulta.py` y `AI_PRE_LLM_CONTRACT.md`: **sin tocar**. ✅
`08_DATABASE/AI_PRE_LLM_CONTRACT.md` §188 contiene:

```text
evidencia.state_version = dataset_id real del mundo que produjo el dato
```

**No se ha modificado.** Es un contrato congelado (regla 2), y su frase es
descriptiva del valor, no una promesa de exclusividad temporal: dice de dónde
sale el valor, no que detecte el estado del mundo.

**Incompatibilidad registrada, no resuelta:** ese documento sigue diciendo «del
mundo que produjo el dato», y ahora se sabe que identifica contenido, no mundo.
Corregirlo exige tocar un contrato congelado y por tanto **queda fuera de esta
misión**. Se anota para que la decisión sea explícita cuando se levante el
congelamiento.

**Nada se propaga a la API en esta misión.** La regla 13 lo permite, no lo exige.
